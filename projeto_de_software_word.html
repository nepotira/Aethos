5. PROJETO DE SOFTWARE

Diante dos problemas de mobilidade urbana e da dificuldade em localizar pontos de prática esportiva na região, a equipe propôs o desenvolvimento do Aethos, uma aplicação web mobile-first modularizada para desktop. A escolha por uma aplicação web fundamenta-se na facilidade de distribuição, independência de instalação de pacotes em lojas de aplicativos e alta compatibilidade cross-platform (iOS, Android, Windows, macOS).

O sistema opera sob o padrão cliente-servidor de três camadas estruturado da seguinte forma:

  • Camada de Apresentação (Frontend): Construída de forma modular utilizando HTML5, CSS3 (Tailwind CSS e Liquid Glassmorphic styling) e lógica cliente em jQuery/JavaScript, integrando APIs geográficas diretamente no navegador.
  • Camada de Aplicação/Negócio (Backend): Desenvolvida em PHP, responsável pelas validações de regras de negócios (verificação de CPF, checagem de e-mails existentes, gerenciamento de sessões seguras e controle de autenticação administrativa).
  • Camada de Dados (Banco de Dados): Gerenciada pelo SGBD MySQL, garantindo consistência relacional e armazenamento seguro por meio de hashing BCRYPT para senhas.

5.1 Concepção do software

A arquitetura do Aethos baseia-se em baixo acoplamento e independência de componentes. O diagrama de componentes a seguir descreve a organização modular do frontend, do backend PHP e sua comunicação com o banco de dados e APIs externas.

O fluxo de dados inicia-se no cliente que realiza requisições assíncronas assinaladas via AJAX. Essas requisições chegam aos endpoints correspondentes no PHP, que valida o estado e consulta o banco de dados via PDO para retornar respostas formatadas em JSON.

5.2 Requisitos funcionais e não-funcionais

A engenharia de requisitos do Aethos seguiu as regras de especificação de software para garantir que todas as necessidades dos perfis de usuário (Atleta, Professor, Administrador e Desenvolvedor) fossem mapeadas com clareza.

Tabela 1 - Requisitos Funcionais do Sistema (Parte 1)

ID Nome Descrição Prior. Tipo
RF01 Cadastro de Atletas Permitir o cadastro de usuários comuns (atletas) com Foto, Nome, Apelido, DDD, Telefone, E-mail e Senha. Alta Cad.
RF02 Cadastro de Professores Permitir o cadastro de professores com campos obrigatórios adicionais: Endereço Fixo e CPF. Alta Cad.
RF03 Validação de CPF Validar a integridade e veracidade do CPF informado pelo professor no cadastro. Alta Regra
RF04 Autenticação por Perfil Efetuar login no sistema diferenciando os níveis de acesso de cada usuário. Alta Seg.
RF05 Login Dev por Nome Permitir acesso de desenvolvedores digitando o nome (ex. Arthur, Lorrany, Nepo) ao invés do e-mail. Alta Seg.
RF06 Troca de Senha Obrigatória Exigir a troca da senha padrão inicial ("senha123") no primeiro login de Administradores/Desenvolvedores. Alta Seg.
RF07 Exibir/Ocultar Senha Fornecer o botão de olho nas senhas para exibir ou ocultar os caracteres. Média Int.
RF08 Solicitação de Localização Pedir autorização do usuário antes de capturar e usar sua localização GPS. Alta Geol.
RF09 Centralização no Mapa Centralizar o mapa na localização GPS do usuário após obtenção dos dados. Alta Int.
